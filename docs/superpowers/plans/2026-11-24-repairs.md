# Repairs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop wrong and silently missing results, cut the app's writes to the shared disk, and make progress lines honest, without changing how bids are decided.

**Architecture:** Targeted fixes where each defect lives: the chat/schema window code, the collector and HTTP error rules, the three caches, the searcher's title screen, the run store, the rate limiter, and a new retention job. On the web side: copy, the empty state, the status poll and the narrow layout. Every fix comes with a test. No pipeline step is added or removed.

**Tech Stack:** Python 3.11 (uv, pytest, pydantic v2, FastAPI, langgraph), React 19 + Vite + Vitest.

**Spec:** `docs/superpowers/specs/2026-11-24-repairs-design.md`

## Global Constraints

- **Shared spinning disk:**
  - Run `cat /proc/pressure/io` before the full test suites and before any live test. Above ~20%, wait.
  - Run one live search at a time, and never leave a server running.
- **Commits:** authored as rjdiips, with no AI `Co-Authored-By` trailer. Use this form:
  ```bash
  GIT_AUTHOR_NAME=rjdiips GIT_AUTHOR_EMAIL=rjdiips@gmail.com GIT_COMMITTER_NAME=rjdiips GIT_COMMITTER_EMAIL=rjdiips@gmail.com git commit -m "..."
  ```
- **Never `git add -A`.** The working tree has the user's unrelated prototype changes, so add only the files a task names.
- **Model-facing pydantic schemas keep every field required.** vLLM enforces the schema, and a field with a default is one the model may leave out.
- **Stored runs still load.** `data/runs` is tracked in git and holds old `outcomes.json`, `run.json` with `limit`, and probes with `window_count`, and these must keep loading.
- **New run files stay text** (JSON/JSONL), so they diff cleanly in git.
- **No new background job runs more often than hourly, and no retry loop runs without backoff.**
- **Test commands:**
  - Backend: `uv run pytest <path> -q`.
  - Frontend: `cd web && npx vitest run <path>`.
  - Full suites: `uv run pytest -q -m "not live"` and `cd web && npx vitest run && npm run build`.

## Review Focus

1. **Runs stored before these changes** (`outcomes.json`, `limit` in `run.json`, `window_count` in probes, verdict files without a version) still open in the UI and the CLI. Tests are in Tasks 1, 3, 5 and 6.
2. **A request with numbers that aren't dates** ("ISO 27001 audit tenders", "AML tenders FY 2026-27", "top 10 bank tenders") is not treated as naming dates. Test in Task 1.
3. **A crash in the middle of an append leaves a truncated last line** in `outcomes.jsonl`. Reading skips that line instead of failing the run. Test in Task 6.
4. **Two runs judge the same bid for the same topic at once.** Neither fails on the shared temp file. Test in Task 3.
5. **Retention never deletes documents of a bid in a running run or in the labelled eval set.** Test in Task 8.
